01 · 카카오테크 캠퍼스 4기

잇다기관마다 흩어진 장애아동 돌봄 기록을 보호자 동의 범위 안에서 잇는 서비스

2026.05 – 진행 중PM · 매칭 에이전트 개발

아동 기록은 민감 정보입니다. 기능보다 먼저 "누구의 기록이, 언제, 누구에게 가도 되는가"를 정책으로 정했습니다.

GitHub
98.2%테스트셋 1,010건 매칭 정확도
3건연동 전에 찾은 BE 계약 불일치

01문제

동의 없이 흐르거나, 기록이 사라지면 사고다

  • 보호자 동의 전에 AI가 기록을 처리하면 안 됩니다.
  • 원본 일지에는 진단명·연락처가 섞여 있습니다.
  • AI 확신도는 같은 입력에도 0.72~0.98로 흔들렸습니다.

02정한 정책 · 규칙

상태가 처리 여부를 정한다

  • 아동은 PENDING_CONSENT로 생성합니다. 동의 전에는 파이프라인을 멈춥니다.
  • 동의는 기관별로 관리합니다. 원본 일지는 기관을 넘지 않습니다.
  • 다른 기관에는 승인된 요약만 인사이트로 공유합니다.
  • 철회 시 행을 지우지 않고 REVOKED로 남깁니다. 삭제는 deleted_at으로 표시합니다.

03시스템에 반영한 방법

규칙을 코드와 테스트로 고정

  • 개인정보는 2단으로 막습니다. BLOCK은 요약 이전에 끊습니다.
  • 담당자 확인 여부는 확신도가 아닌 구조적 조건으로 정합니다. 후보가 한 명이고 본문에 근거가 있을 때만 자동 확정합니다.
  • 기준 문서 → config → 테스트 순서를 지킵니다. 순서가 반대면 기준이 코드를 따라갑니다.
  • 입출력 계약을 pydantic으로 고정해 BE와 어긋난 3건을 연동 전에 찾았습니다.

04결과

같은 입력에 같은 판정

  • 테스트셋 1,010건에서 매칭 정확도 98.2%를 얻었습니다.
  • 철회 이력이 남아 "누구 정보를 누구에게 줬는지" 추적할 수 있습니다.

02 · 산학협력 (주)인비고웍스

BEFORE미국주식 하방 리스크를 먼저 보여주는 서비스

백엔드 · 인증 · 계정 관리토스 미니앱 출시

투자 정보 서비스라 면책 동의 없는 계정은 존재하면 안 됩니다. 토큰이 탈취되면 그 세션을 한 번에 끊을 수 있어야 했습니다.

GitHub · Server
1만명토스 미니앱 누적 사용자
최우수상산학협력 경진대회 · SW 저작권 등록

01문제

계정과 동의가 따로 놀면 안 된다

  • 가입은 됐는데 면책 동의가 빠진 계정이 생길 수 있었습니다.
  • Refresh 토큰이 탈취되면 공격자 세션을 끊을 방법이 없었습니다.
  • 장애 원인을 한곳에서 추적할 수단이 필요했습니다.

02정한 정책 · 규칙

가입 = 동의, 재사용 = 탈취

  • 가입과 면책 동의는 함께 성공하거나 함께 실패합니다.
  • Refresh 토큰은 한 번만 씁니다. 폐기된 토큰이 다시 오면 탈취로 봅니다.
  • 탈취가 의심되면 그 로그인에서 나온 세션을 모두 끊습니다.
  • 비밀번호는 Argon2 해시로만 저장합니다.

03시스템에 반영한 방법

트랜잭션과 토큰 family

  • users와 disclaimer_acks INSERT를 한 트랜잭션으로 묶었습니다.
  • JWT Refresh Rotation에 family_id를 붙여 일괄 무효화를 구현했습니다.
  • ELK로 로그를 중앙화해 장애 원인을 추적했습니다.
  • 알림 단계를 분리해 다른 단계 장애가 번지지 않게 했습니다.

04결과

출시하고 1만 명이 썼다

  • 토스 미니앱으로 출시해 누적 사용자 1만 명을 넘었습니다.
  • SW 저작권을 등록했습니다.
  • 산학협력 경진대회에서 최우수상을 받았습니다.
